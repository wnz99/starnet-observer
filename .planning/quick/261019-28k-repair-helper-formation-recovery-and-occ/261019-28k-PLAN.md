# Helper formation recovery implementation plan

Semantic revision: 1. Baseline: `61994227dd8a6627ebc8738f46ef505fbadba500`.

## Features and effects

Fresh helpers should form a compact crew around their moving leader wherever the current room permits it. Earlier furniture encounters must not leave eight helpers parked along a U-shaped trail after their leader reaches open floor. Dotted desk links should disappear as soon as a helper leaves its own chair.

### F1: Recover and maintain a compact following crew

- Problem and current behavior: pair destinations come exclusively from the leader's past route. One obstructed historical stripe rejects the whole group. A resting leader cannot change those destinations, and followers reject replacement destinations at an unchanged history arc. A deterministic fresh eight-helper scene remains spread after 34 seconds of open rest despite clear, reachable compact slots.
- Proposed behavior: choose collision-proven paired rows near the leader's current position. Keep ordered single file where current geometry prevents compact rows. Recover after narrow doors and short turns, during walks and rests. One helper occupies a centered slot; odd groups have a centered tail.
- Effect on the code: replace the historical-only pair proposal inside the existing formation planner; distinguish compact spatial targets from historical single-file targets in the existing actor follower. Give following helpers a capped acquisition speed of 2.4 world units/second so they can regain distance while their leader walks at 1.6. Normal roaming, home returns and lifecycle travel retain 1.6.
- Scope and compatibility: preserve observed helper status, verified immediate-parent lineage, nested depth rules, collision checks, stale and ancestor freeze, own working/blocked returns, reduced motion and bounded history. No source-freshness change, new dependency, service, production debug API or user setting.
- Acceptance outcomes: every admitted helper settles into compact rows at independently clear natural rests; sustained open walks and turn exits reacquire rows within a geometry-derived deadline. All movement remains bounded and obstacle-safe. Genuinely narrow doors still use ordered single file.
- Execution mapping: Task 1; acceptance A1–A5.

### F2: Show desk links only for occupied helper chairs

- Problem and current behavior: links live in the cached static floor and remain visible when helpers walk away.
- Proposed behavior: show a helper's existing dotted connector only when that helper's current frame is at its own chair. Departure, idle away, return transit, stale-away and a missing actor hide it. Arrival and reduced-motion chair snaps show it.
- Effect on the code: move the existing line style and drawing into the per-frame world pass, after the cached floor and before actors/furniture. Keep the static cache independent of actor positions.
- Scope and compatibility: retain connector endpoints, accent, dash, alpha and width in both station and office art. Ambient effects settings must not disable occupied links.
- Acceptance outcomes: rendering-command evidence covers departure through return in both art modes; repeated motion frames reuse the static cache.
- Execution mapping: Task 2; acceptance A6–A7.

## High-level design and rationale

The proven cause is historical destination selection and same-arc rejection, not stale data. The design below is a proposed correction, not a claim that a particular implementation has passed. Investigation details and reproducible probes are in `DISCOVERY.md`.

Use one group policy in `FormationPlanner`: compact targets when the current footprint is clear, historical single file otherwise. Reuse the existing 1.6 first-row lag, 1.2 row gap, 0.6 side offset, helperSlot ordering and 0.8-unit target quantization. Current-position targets must not replay obsolete offset bends. Historical traversal remains responsible for safe, ordered passage through constrictions.

At a moving leader, use its latest nonzero travel tangent. At rest, retain a valid current orientation; if blocked, try that tangent, its opposite and its two perpendiculars in a fixed order. Admit an orientation only when every member slot and the connecting row/center stripes pass the existing inflated helper envelope check. Route actual joins through `safeSegment`/`pathTo`; an unavailable route is a failed candidate, never permission to snap or cross furniture. Cache each bounded proposal by parent quantized position/heading, membership and graph identity. A first stationary proposal must be evaluated even at streak zero; no follower-success precondition may gate recovery. A stopped leader uses its exact endpoint, not only the last quantized point.

Compact assignments carry spatial identity. The actor accepts changed compact coordinates even when the parent arc is unchanged; historical assignments retain the monotonic arc cursor. Recompute compact paths only when their quantized target changes or the mode/membership/geometry invalidates them. Do not interrupt a path for unchanged targets. Prefer a safe direct join; use the existing bounded graph search otherwise. Capped follower acquisition speed addresses the separately proven equal-speed lag without removing collision checks or allowing teleports.

- Design choices: replace the obsolete historical pair controller rather than bolt on a second recovery state machine. Keep only `single` and `pairs` group modes. Reuse the navigation graph and the existing per-frame group planning map. No generic slot engine, persistence, retry scheduler, new observer integration or per-frame static invalidation.
- Risks and safeguards: current footprints can become unsafe at turns or doors; fall back immediately and invalidate compact routes. A compact replan must start from the current foot and prove the complete route. Endpoint-only checks are insufficient. Heading changes can churn paths; use the existing spatial bucket and retain stable orientation at rest. Catch-up changes a visible speed bound, so assert the new 2.4 cap only for actual following and retain the old 1.6 cap elsewhere. A helper's own status and stale freeze always take priority.
- Rollback: revert the bounded feature commits; no schema, data migration or deployment state is involved.
- Decisions selected for review: current-position compact policy, 2.4 maximum following speed, existing 0.001 chair tolerance, two sequential tasks. No unresolved product question is required for this bounded fix. Independent plan review still owns its verdict.
