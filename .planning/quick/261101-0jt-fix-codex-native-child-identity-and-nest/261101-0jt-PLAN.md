## Features and effects

### F1: Discover and inspect direct and nested native children safely

- Problem: the current dirty patch accepts direct native children by treating the shared session ID as the immediate parent ID and inventing a fork boundary. A grandchild shares its root's session ID while naming its immediate parent separately, so that rule rejects valid nested children.
- Proposed behavior: a root R discovers child C and grandchild G with no SQLite edges. G has `id=G`, `session_id=R`, and `parent_thread_id=C`. Both helpers show their own transcript and usage, with exact lineage and inherited grouping.
- Effect on code: one metadata decoder owns Codex child identity and history semantics. Binding carries verified root identity separately from optional inherited-history exclusion. Discovery, inspection and spawn indexing consume that contract.
- Scope and compatibility: preserve existing legacy children and explicit paginated forks, Claude handling, bounded reads, graph limits, duplicate/cycle rejection, rewrite checks and stale presentation. No new dependencies, services, format framework, user configuration, public UI changes or real controls.
- Acceptance: native direct/nested helpers remain inspectable; inherited content never contributes turns, usage or spawn claims; ambiguous or contradictory identity remains unavailable.
- Execution mapping: Task 1.

## High-level design and rationale

Keep this one cohesive task: metadata decoding, proof propagation and all projection consumers share one security-sensitive contract. Splitting them would create transient incompatible states.

Add a small validated Codex child metadata value to the existing binding. It records shared root session identity and an optional own-history start ordinal. Native own-only history has no synthetic fork boundary; explicit inheritance has a validated boundary. Keep format decisions in `inspector/identity.ts`, alongside current record ownership rules. `transcripts/identity.ts` establishes and rechecks that value; other consumers compare or use it, rather than reconstructing source rules.

Pass a proved parent binding through existing child-binding calls for nested children. A root supplies its exact verified session ID; a nested parent supplies its registered binding's shared root ID. Never learn a supposedly verified root from the candidate child's unchecked `session_id`. Verify ownership chains ancestor-first so their root expectation is available for each edge. Because ownership stops at the nearest observed ancestor, retain that ancestor's terminal registered binding alongside its grouping owner during the ownership pass. Seed the next chain from this retained proof. Keep these proof bindings local to ownership: adding them to traversal's represented bindings would bypass depth/total limits.

Retain existing containment and file proof mechanisms. Metadata acceptance does not authorize reading `history_base` files. Separate prefix storage from own-history boundaries; unsupported or ambiguous history combinations fail closed.

- Design choice: reuse `ChildBinding`, `Children`, `HelperTraversal`, `HelperGraph`, Reader and SpawnIndices rather than adding a parallel discovery or ancestry service.
- Risks and safeguards: mutable or reused bindings could retain old identity proof; freeze the decoded value, compare it on every revalidation, and include its semantic fields in caches. Contradictory aliases must fail before projection is committed.
- Compatibility: ordinary legacy headers retain existing exact alias rules. Existing supported fork fixtures remain valid. Expanded root alias acceptance applies only to proved native/fork metadata.

## Data-flow analysis

| Stage | Input and source | Processing and owner | Output | Material failure handling |
| --- | --- | --- | --- | --- |
| Candidate | SQLite edge or verified parent's spawn projection | Existing graph/traversal checks | Exact child and immediate parent IDs plus optional registered parent binding | Duplicate parents, cycles and invalid IDs remain rejected |
| Bind | Contained child file prefix and trusted parent context, including retained proof for an already-owned observed ancestor | Children obtains root expectation; ChildIdentity invokes owning decoder; ownership carries terminal proof across observed boundaries | Frozen identity/history metadata in registered ChildBinding; local ownership proof separate from represented bindings | Unregistered/missing required parent proof, wrong root, wrong parent, conflicting aliases or unknown history reject |
| Project | Complete bounded records or bounded spawn-index chunks | `belongs` and `inheritedRecord` apply decoded contract | Own turns, usage and helper activity | Inherited records excluded; invalid own ordinals excluded; conflicting metadata invalidates proof |
| Refresh | Same binding with current file prefix/tail | Reader and SpawnScan compare current proof with bound metadata | Fresh projection or unavailable result | Header rewrite, inode swap and changed proof cannot reuse prior claims |

Example: G's `session_id=R` is an allowed header alias only when C's registered binding already proves R. G's `thread_id`, when present, must equal G. Own ordinary records retain existing child-thread identity checks; shared root alias support does not globally permit parent-tagged content.

**Intended edits:**

1. Define `CodexChildMetadata = { rootSessionId: string; historyStartOrdinal?: number | undefined }` in inspector contracts and `ChildBinding.codexMetadata?: CodexChildMetadata | undefined`. This is runtime-internal proof metadata, never serialized into browser rows. Replace the old top-level `historyStartOrdinal` field and all consumers rather than retaining dual state.
2. Replace `forkHistoryStart`/`nativeChild` with `decodeCodexChildMetadata(payload: Record<string, unknown>, child: string, parent: string, root: string): CodexChildMetadata | null`. Validate aliases once. `id=child`, optional `thread_id=child`, exact `parent_thread_id=parent`; shared-root aliases require `session_id=root`, v2/paginated and matching native `source.subagent.thread_spawn.parent_thread_id` when native provenance is required. Legacy headers with absent/child `session_id` retain current exact behavior and must not gain shared aliases merely from a boundary.
3. History rules: native own-only requires absent fork/inheritance fields and matching native source; return no boundary. Explicit supported fork requires exact `forked_from_id=parent` and positive safe-integer own-history boundary. Validate any present native source against parent even on a fork. A nonempty `history_base` without an explicit own-history boundary is unavailable; do not fetch its target or substitute its prefix ordinal. With explicit supported history, validate `history_base` shape (`thread_id` UUID, nonnegative safe `end_ordinal_exclusive`/`end_byte_offset`) but do not require its rollout ID to equal parent. Unknown versions/modes or partial/contradictory history fields fail closed. Optional absent fields are distinct from malformed values; only documented omission forms are accepted.
4. `ChildIdentity` decodes the canonical first metadata record, verifies ordinal zero for paginated metadata, stores a frozen decoded value before binding registration, and compares it on later reads. Exact legacy metadata retains existing no-ordinal support. It must never rewrite a frozen binding's proof. Repeated own metadata rejects; inherited metadata is ignored only after canonical proof and only below an explicit valid boundary.
5. Change `bindChild`/`Children.bind` to append sixth optional parameter `parentBinding?: ChildBinding`. Existing five-argument consumers remain valid. When supplied, require WeakSet registration, provider Codex and `parentBinding.sessionId===parent`; derive expected root from its decoded metadata, otherwise the exact parent ID. Append optional `parentBinding?: ChildBinding` after `candidate` on `HelperTraversal.prove`; propagate from `visit`, and include expected root in memoization. Extend graph-local `Prove` with fourth optional `parentBinding?: ChildBinding`; `discover` forwards it as the fifth `prove` argument with `candidate=undefined`.
   - Keep `HelperGraph.ownership`'s return contract `Map<string, Root>` for grouping/suppression. Add a pass-local `Map<string, ChildBinding>` keyed by observed row ID for terminal ownership proofs. Existing depth-sorted root order must run ancestors before descendants.
   - For `found.ancestor` already in ownership, require its terminal proof from this local map; missing proof rejects the chain, with no fallback to an exact-parent root. Otherwise seed with no binding and use that independently observed ancestor's exact verified session ID as root authority. Never seed from candidate metadata or the grouping owner's session ID alone.
   - Walk `found.chain` in reverse with this seed. Each edge calls `prove("codex", edge.child, edge.parent, parentBinding)` and carries the returned registered binding forward. Publish both the inherited grouping owner and the terminal binding for `row.id` only after every edge succeeds; discard partial proof on failure. Thus R→C stores C's proof, then a chain G→C starts with C's proof even though R is absent from that chain.
   - Do not insert ownership-only proofs into `HelperTraversal.bindings`, increment represented-helper counts, or advertise helper parents for omitted rows. Preserve `chain` cycle/ambiguity guards, MAX_DEPTH/MAX_HELPERS and existing independent-root behavior where no ancestor ownership was proved. Do not use unchecked child headers as root authority.
6. `belongs`, `inheritedRecord` and own-record filtering read decoded metadata. No boundary means no ordinal exclusion solely because a native child exists. An explicit boundary excludes records below it, requires safe own ordinals, and permits only canonical metadata at ordinal zero. Keep existing ordinary record child-ID checks; reject contradictory aliases.
7. Update Reader cache/pending keys and SpawnIndices key with the small decoded identity tuple (root ID and boundary). Revalidate the child header with `childMetadata` before SpawnScan reuses or publishes a child projection. Contradiction invalidates the scan result, including stale claims. Keep full-prefix hashes, read/line/size caps, resource verification and unavailable handling. Do not add a cache abstraction or a generic format registry.
