## High-level design and rationale

Use one optional standalone Bun entrypoint under existing `scripts/*.ts` build/scanner registration, one small sidecar-owned store, and current observer refresh/publication ownership gates. No daemon, hook-provider schema, package dependency, bus configuration or transcript parsing is added.

The recorder captures `process.cwd()` plus canonical `realpath` at invocation, not `PWD`, argv, shell strings, transcript JavaScript or output prose. Codex identity is `CODEX_THREAD_ID` only; inherited `CODEX_SESSION_ID` never substitutes. Environment identity is a local opt-in claim, not a security boundary against malicious code running as the same user. Only already verified observer session identities may consume it. No record creates a session, helper edge or control permission.

A separately owned printed .zshenv snippet invokes the recorder synchronously through absolute, shell-quoted Bun and emitted entrypoint paths, guarded by a nonempty thread ID and executable/file existence. It suppresses output and tolerates failure without changing cwd, shell exit status or options. No .zshrc-only promise: normal noninteractive nonlogin zsh loads .zshenv. Startup flags, snapshots or ZDOTDIR overrides can bypass it; documentation states limited coverage. The CLI prints preview only and has no install subcommand. A future shared-settings edit requires final explicit user authorization after tested preview is reviewable.

Each event is an immutable, exclusively created 0600 JSON file in a 0700 per-thread directory under `~/.local/share/starnet-observer/tool-workdirs/v1/codex/`. Unique timestamp/random filenames prevent simultaneous writers from replacing a newer event. Reader selects greatest original observedAt, with deterministic filename tie order; tie order has no task-current meaning. Read at most 128 directory entries and 4096 bytes per event, reject overflow as unavailable instead of claiming exhaustive latest evidence. Recorder prunes only validated same-session regular events, first expired records, then oldest observations beyond the newest 64, before and after its exclusive write. Concurrent pruning tolerates ENOENT and never deletes an event newer than its captured retained set. Never recursively clean or touch another session directory. Normal reads never mutate. An already overflowing directory fails closed without an unbounded cleanup scan. Coverage is “most recent recorded shell entry”, never every command.

Reject symlink/non-directory roots, nonregular event files, foreign ownership, group/world-accessible state directories/files, path containment violations, descriptor/path identity changes and malformed payloads. Use no-follow opening and descriptor revalidation following `transcripts/resources.ts:Resources` patterns; do not weaken existing transcript checks or make them a generic filesystem framework. Same-user arbitrary code remains capable of impersonating this opt-in signal, as with other local state.

Risks: synchronous Bun startup adds shell-entry cost; test measured no-network success/failure behavior and disclose observed cost without an invented budget. Failed Git discovery, read bounds or exact identity gates reduce coverage honestly. Revert removes code; disabling/removing an approved snippet is the installation rollback. This task installs nothing.
